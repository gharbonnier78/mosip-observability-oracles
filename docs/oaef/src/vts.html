1 Introduction

1.1 Purpose

This document specifies how to validate that the Observability and Audit Evidence Framework (OAEF), once implemented and deployed, meets the requirements of OAEF-SPEC-001. Its structure follows ISO/IEC/IEEE 29119-3: test plan (chapter 2), test design (chapter 3), test environment and data (chapter 4), test procedures (chapter 5), test cases (chapter 6), traceability (chapter 7) and completion report template (chapter 8).

2 Test plan

2.1 Test items

  • Generic layer: instrumentation conditions, collector agent and gateway, Tempo, Loki (app and audit tenants), Mimir, Grafana, object storage.
  • Deployment: Terraform modules, Helm values, Argo CD applications, overlays generated from the environment manager.
  • Qualification layer: Jarvis, data generator, mocks, evidence collector, oracle engine, reporter.
  • Reference implementation: NIN-001 oracle, feature, persona and prerequisites.

2.2 Features to be tested

All requirements of OAEF-SPEC-001 chapter 5 (SW, TST, INF, SEC, DQ, OPS). Features not tested in this version: production monitoring service levels; performance of MOSIP itself.

2.3 Approach

  1. Phase V1 — Simulation: VT-INF, VT-PIPE, VT-SEC (mode S), VT-QUAL. Demonstrates the pipeline, storage, security controls and verdict logic with controlled inputs, including injected faults.
  2. Phase V2 — Full NIN-001: VT-SW, VT-E2E. Demonstrates the real instrumentation of MOSIP and the full evidence chain.
  3. Phase V3 — Inspection and demonstration: remaining I and D test cases, sign-off.

Each test case produces its own evidence (chapter 6) stored in the evidence bucket under validation/<campaign-id>/<test-case-id>/.

2.4 Entry criteria

  • V1: observability stack and qualification tooling deployed on the target platform by GitOps; telemetrygen available at the pinned version; credentials for read-only service accounts.
  • V2: MOSIP test platform deployed; prerequisites env-nin-baseline green; MOSIP extension and audit patch deployed.

2.5 Exit criteria

  • All test cases covering M requirements passed; no open defect of severity critical or major.
  • VT-E2E-01 passed twice consecutively on TEST with identical verdicts.
  • Every requirement of OAEF-SPEC-001 covered by at least one passed test case (chapter 7).

2.6 Suspension and resumption

Suspend when the pipeline-health objectives are breached (results would be INCONCLUSIVE) or when the platform drifts from the environment manager. Resume after correction and a passing VT-INF-01 canary.

5 Test procedures

5.1 TP-1 Replay of the NIN-001 OTLP example (simulation)

The example must be replayed with new trace and span identifiers and current timestamps, so that each replay is unique and inside the retention window. Python handles the 64-bit nanosecond integers exactly.

#!/usr/bin/env python3
# replay_nin001.py  —  usage: python3 replay_nin001.py NIN-001.otlp-example.json http://AGENT:4318
import json, os, sys, time, urllib.request
src, endpoint = sys.argv[1], sys.argv[2].rstrip('/')
doc = json.load(open(src, encoding='utf-8'))
ids = {}
def new_id(old, n):
    if not old: return old
    return ids.setdefault(old, os.urandom(n).hex())
t_min = min(int(s['startTimeUnixNano']) for rs in doc['traces']['resourceSpans']
            for ss in rs['scopeSpans'] for s in ss['spans'])
shift = time.time_ns() - t_min - 60_000_000_000          # start one minute ago
def fix(o):
    if isinstance(o, dict):
        for k, v in list(o.items()):
            if k.endswith('UnixNano') and isinstance(v, str): o[k] = str(int(v) + shift)
            elif k == 'traceId': o[k] = new_id(v, 16)
            elif k in ('spanId', 'parentSpanId'): o[k] = new_id(v, 8)
            else: fix(v)
    elif isinstance(o, list):
        for x in o: fix(x)
for block in ('traces', 'logs', 'metrics'): fix(doc[block])
for block, path in (('traces', '/v1/traces'), ('logs', '/v1/logs'), ('metrics', '/v1/metrics')):
    req = urllib.request.Request(endpoint + path, data=json.dumps(doc[block]).encode(),
                                 headers={'Content-Type': 'application/json'})
    print(block, urllib.request.urlopen(req).status)
root = ids['4bf92f3577b34da6a3ce929d0e0e4736']
print('replayed trace id:', root)

Verification queries (replace <trace_id> with the printed id):

curl -s "$TEMPO/api/v2/traces/<trace_id>"                       # 7 spans, ids returned base64: normalise to hex
curl -s -G "$LOKI/loki/api/v1/query_range" -H "X-Scope-OrgID: app" \
     --data-urlencode 'query={service_name="regproc-pkr"} | trace_id="<trace_id>"'
curl -s -G "$MIMIR/prometheus/api/v1/query_exemplars" \
     --data-urlencode 'query=http_server_request_duration_seconds_bucket{job="regproc-pkr"}' \
     --data-urlencode "start=$(date -d '-10 min' +%s)" --data-urlencode "end=$(date +%s)"

telemetrygen logs --otlp-endpoint $AGENT:4317 --otlp-insecure --logs 20 \

5.4 TP-4 Full NIN-001 run

  1. Resolve the target environment (for example test-int@DC1) and run the prerequisite checks.
  2. Execute features/nin_001_new_adult_no_hit.feature with Jarvis.
  3. Let Jarvis settle, collect, seal and verify; archive the report and the evidence bundle.
  4. Verify the bundle signature and hashes independently.
